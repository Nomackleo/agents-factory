---

## 1. Descripción del Ecosistema

El **Minimal Coding Ecosystem** es un subsistema agéntico elástico y modular diseñado para tareas de programación, refactorización y optimización extrema de bases de código. Combina el paradigma del *Lazy Senior Dev* (repositorio `Nomackleo/ponytail`) con el marco **Spec-Driven Development (SDD)** de GitHub (`github/spec-kit` / `specify-cli`).

Este ecosistema reduce drásticamente el volumen de líneas de código escritas (hasta -54%), el consumo de tokens (-20%) y la latencia (-27%), haciendo que **las especificaciones sean ejecutables** y manteniendo al **100% la seguridad, validación de fronteras, manejo de errores y accesibilidad**.

---

## 2. Arquitectura de Guilds y Subagentes

El ecosistema se organiza en el `minimal-coding-guild`:

* `spec-driven-developer`: Orquesta el ciclo de vida SDD (`/speckit.constitution`, `/speckit.specify`, `/speckit.plan`, `/speckit.tasks`, `/speckit.implement`) convirtiendo requerimientos ambiguos en especificaciones ejecutables.
* `minimal-architect-checker`: Inspecciona la base de código previa, valida el plan de arquitectura (`/speckit.plan`) y bloquea dependencias innecesarias reutilizando código preexistente o librerías estándar.
* `minimal-code-refactorer`: Ejecuta tareas de especificación (`/speckit.implement`) aplicando la **Escalera de Deducción (Ladder of Deduction)** de 7 niveles.
* `minimal-qa-gatekeeper`: Valida el cumplimiento de la constitución del proyecto (`/speckit.constitution`), seguridad ISO 27001 / SOC 2 y pruebas TDD.

---

## 3. Flujo SDD + Escalera de Deducción (Ladder of Deduction)

```
[ Requerimiento ] → /speckit.specify → /speckit.plan → /speckit.tasks
                                                              ↓
                                                    /speckit.implement
                                                              ↓
                                            1. ¿Necesario? (YAGNI -> Omitir)
                                            2. ¿Existe en codebase? → Reutilizar
                                            3. ¿Librería estándar? → Usar stdlib
                                            4. ¿Nativo platform/browser? → Solución nativa
                                            5. ¿Dependencia instalada? → Reutilizar paquete
                                            6. ¿1 línea? → One-liner
                                            7. Último caso: → Mínimo código funcional
```
